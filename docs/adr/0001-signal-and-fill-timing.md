# ADR 0001: Signal and fill timing

- Status: Accepted
- Date: 2026-08-24

## Context

The original daily backtest could rank securities with a completed session's
close, amount, and close-derived features and fill at that same close.  Those
inputs are not all known early enough to guarantee that fill, so the model
contained same-bar look-ahead.

## Decision

The default daily research model is:

```text
session t closes
→ features and rankings are computed after the close
→ orders become eligible for the next trading session
→ fills use session t+1 raw open prices
```

The following invariant applies to every formal run:

```text
feature_available_at <= decision_ts < fill_ts
```

Adjusted prices may be used to build features, but simulated cash and trades use
raw executable prices.  Missing ST, suspension, price-limit, listing, delisting,
or availability fields are blocking errors for a strict research snapshot; they
must not be silently replaced with optimistic defaults.

Any alternative execution convention must have a distinct explicit name, must
document its decision and fill timestamps, and must have a regression test that
prevents same-bar information leakage.

## Consequences

- Results generated by the earlier same-close convention are legacy artifacts,
  not evidence for the corrected engine.
- The first eligible session after a rebalance signal may be blocked by
  suspension or price limits; an order is not assumed to fill merely because a
  target portfolio exists.
- Reproducible runs record the snapshot ID, both repository commits, timing rule,
  costs, and configuration hash in an experiment receipt.
